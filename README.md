# 舞萌报卡（maimai_card_report）

面向舞萌 / 音游机厅的排队报卡 AstrBot 插件。支持机厅与群号绑定、多机台多方位报卡识别、
排卡人数查询、超时自动清零、异常报卡过滤与黑名单，以及每日开门 / 闭店语自动生成发送，
并提供完整的 WebUI 控制面板。

> 兼容 AstrBot >= 4.28.2，已在 4.29.3 上验证核心 API。

## 功能特性

- **机厅配置管理**：机厅名称 / 别名 / 绑定群号，多机台、多方位的完整配置与校验。
- **群号绑定**：消息按群号自动定位机厅；支持跨群、歧义检测与机厅别名指定。
- **报卡识别**：支持 `zy5k`、`zy+1k`、`zy-1`、`z1y2`、`2z3y`、`左2右3`、`中二z1y2`、`内1k外2k` 等格式，
  支持机台别名直接跟人数（`tg2`、`wm3`）、`@机器人` 前缀（`@bot 5k`）、
  累加（`+`）、扣减（`-`，在当前人数上减少且最低到 0）、覆盖、中文数字与全角符号归一化。
  单独出现的纯数字（如 `6`、`666`）不视为报卡，避免群聊数字被误记。
- **排卡查询**：`zyjk`、`兆阳几卡`、`zy?k` 等查询当前排卡人数。
- **超时清零**：超过过期小时数自动清零；支持「方位独立 / 机台共享」两种计时粒度。
- **异常过滤与黑名单**：超范围、无法解析等异常识别；累计 5 次自动封禁（静默忽略），
  第 4 次可调用 LLM 幽默调侃提醒。
- **开门 / 闭店语**：按配置时间自动生成并发送到绑定群（优先使用 LLM 生成，失败回退到默认文案）。
- **插件控制面板**：首页看板（排卡总览 + 黑名单）、机厅管理、设置与调试三个 WebUI 页面。

## 安装

1. 将本插件目录放入 AstrBot 的插件目录，或通过 AstrBot 插件市场安装。
2. 重启 AstrBot 或执行插件重载。
3. 在 AstrBot WebUI 的插件列表中启用「舞萌报卡」。

插件无第三方依赖，仅使用 Python 标准库与 AstrBot 官方 `astrbot.api`。

## 使用说明

报卡与查询为**纯消息触发**，直接向绑定群发送文本即可，无需指令前缀。

| 示例 | 含义 |
| --- | --- |
| `zy5k` | 机厅「兆阳」默认机台报 5 卡 |
| `zy+1k` | 兆阳默认机台累加 1 卡 |
| `zy-1` / `左-2` / `-1k` | 在当前人数上扣减（最低到 0） |
| `z1y2` / `2z3y` | 默认机台左 1 右 2 |
| `左2右3` | 使用方位显示名报卡 |
| `中二z1y2` | 指定「中二」机台报卡 |
| `tg2` / `太鼓2` | 机台别名 + 人数（机台别名在句首时可省单位） |
| `@bot 5k` / `@bot 左3` | 开头的 @ 提及会被忽略，其余照常解析 |
| `内1k外2k` | 内 1 外 2（`inside_outside` 方位） |
| `zyjk` / `兆阳几卡` / `zy?k` | 查询兆阳当前排卡 |

> 机厅可通过别名触发；当群绑定多个机厅时，需要显式指定机厅别名（如 `zy5k`），
> 否则插件会提示存在歧义。
>
> 仅数量报卡必须带单位（`5k` / `5卡` / `5人`）或显式符号（`+1` / `-1`）；
> 单独发送数字（如 `6`、`666`）属于普通聊天，既不报卡也不计入异常次数。
>
> 例外：机台名/别名写在句首时，后面可以直接跟纯数字（`tg2`、`舞萌3`），
> 因为此时目标机台已经明确；机台别名只出现在句子中间时不会放行。

发送 `help`、`帮助` 或 `怎么报卡` 等，机器人会回复规范报卡格式说明与示例；当报卡数值异常或无法识别时，回复中也会附上「发送 help 查看格式」的提示。

## WebUI 控制面板

插件在 AstrBot 侧边栏自动注册一个控制台页面，内部通过顶部页签（Tab）切换三个功能区块：

- **首页看板**：各机厅 / 机台 / 方位排卡人数、上次报卡与下次清零时间，支持修改人数、机台 / 机厅清零，
  并展示黑名单（含首次异常、封禁时间、原始消息等）与解除操作。
- **机厅管理**：新增 / 编辑 / 删除机厅，配置别名、绑定群号、机台与方位别名、过期小时数、
  正常范围、时区、开门 / 闭店语与异常提示模板。
- **设置与调试**：消息解析测试（模拟机厅匹配与报卡 / 查询识别，不写入数据）、操作日志查看。

> 为什么合并为单页面：AstrBot 的插件视图以受限 iframe 嵌入，插件页签（Tab）无法直接调用父页面
> 路由切换视图（沙箱无 `allow-top-navigation`，且父页面未暴露跳转接口）。若拆成多个视图目录，
> 页面内无法互跳，只能依赖侧边栏的「按插件分组」子菜单切换，体验不佳且易触发
> `Token 无效`。因此统一为单个 `dashboard` 视图，用页签在 iframe 内部完成切换。

### 浏览器访问地址

插件页面由 AstrBot 内置的 Dashboard 托管，**可以直接在本地电脑的浏览器中打开**，
功能与在 AstrBot 面板侧边栏点击进入**完全一致**（页面在 AstrBot 前端的 iframe 内运行，
桥接 SDK `window.AstrBotPluginView` 由 AstrBot 注入，`apiGet`/`apiPost` 通过 postMessage 转发）。

默认 Dashboard 监听地址为 `http://localhost:6185`，插件页面访问地址如下：

| 页面 | 访问地址 |
| --- | --- |
| 控制台 | `http://localhost:6185/plugin/maimai_card_report/dashboard` |

> 说明：
> - 上述地址要求 AstrBot 在本机运行且 Dashboard 可访问（默认 `localhost:6185`）。
>   若 AstrBot 部署在远程服务器，请将 `localhost` 替换为服务器 IP / 域名及端口。
> - 请通过上述 `/plugin/...` 路由访问。**不要**直接打开插件数据目录下的 `index.html` 文件，
>   也不要访问桥接后端原始 HTML 路径，否则页面缺少 AstrBot 注入的桥接 SDK，数据接口无法工作。
> - 首次打开会加载页面资源，若显示「加载失败」，请查看本文「日志系统」章节定位原因。

## 配置说明

机厅配置项（在「机厅管理」页面维护，新增机厅时继承全局默认值）：

| 字段 | 说明 |
| --- | --- |
| 名称 / 别名 | 机厅唯一标识与消息触发别名 |
| 绑定群号 | 逗号分隔，用于群号自动定位机厅 |
| 过期小时数 | 报卡后超过该时长自动清零 |
| 清零粒度 | `slot` 方位独立 / `machine` 机台共享 |
| 正常人数范围 | 超出范围视为异常报卡 |
| 时区 / 开门 / 闭店时间 | 用于时间显示与开门 / 闭店语判定 |
| 开门 / 闭店语开关与提示词 | 自动生成公告文案，可留空使用默认 |
| 异常提示模板 | 支持 `{arcade}` `{qq}` `{value}` `{limit}` 变量 |

全局默认值通过 `_conf_schema.json` 暴露在插件配置面板中，供新建机厅时继承。

## 数据存储

数据存放于 AstrBot 插件数据目录（`get_astrbot_plugin_data_path()`），
子目录为 `maimai_card_report/`，包含：

- `arcades.json`：机厅配置
- `records.json`：报卡记录
- `abnormal.json`：异常用户 / 黑名单
- `logs.json`：操作日志
- `state.json`：运行状态（开门 / 闭店语发送标记、群会话映射）

## 日志系统

插件内置**双通道诊断日志**，用于定位报卡识别、WebUI 加载、定时任务等问题：

### 1. 诊断日志（AstrBot 标准日志通道）

所有关键节点的诊断日志统一通过 AstrBot 标准 logger 输出，覆盖：

- **插件生命周期**：初始化、数据目录、WebUI API 注册、定时任务启停与执行结果
- **消息处理链路**：群消息接收（群号 / 发送者 / 原始文本）、机厅匹配、报卡 / 查询结果、异常栈
- **WebUI 请求**：每个 API 请求的方法、路由、状态码、耗时；4xx 记 WARN，5xx 与异常记 ERROR（含堆栈）
- **数据持久化**：数据加载数量汇总、JSON 读取 / 保存失败（含路径与堆栈）
- **开门 / 闭店语**：生成回退、无群会话、发送失败等分支

**存储位置与查看方式**：

- 在 AstrBot 面板右上角「日志」页面直接查看（推荐，支持按级别过滤）。
- 对应文件位于 AstrBot 数据目录下的日志目录，通常为
  `{AstrBot 数据目录}/logs/`（随部署方式不同而略有差异，以面板「日志」页实际展示为准）。

### 2. 操作日志（插件自身）

面向普通管理员的业务操作日志，可在「设置与调试」页面查看，落盘于：

```
{AstrBot 数据目录}/plugin_data/maimai_card_report/logs.json
```

字段：`id` / `ts`（时间戳）/ `level` / `group_id` / `message`，仅保留最近 1000 条。

> 排查建议：优先看面板「日志」页（诊断日志含完整堆栈）；若需判断某次报卡 / 配置操作是否生效，
> 再结合 `logs.json` 与「设置与调试」页面的操作日志。
